## 按 §11 十四问

**1. 自然语言目标解析是否接入宿主？**
代码级已接入：app.py 2a-pre.4c → `taskloop_host.handle` → `nlp.ask
("goal_parse")` → `taskloop.parse_goal`。链路为编译+假模型集成验证；
**真实 LLM 解析未跑**（§10 计划待授权）。

**2. 结构化目标与约束是否校验？**
是（离线 8+3 例）：非结构输出→reject 不执行；questions 非空→ask；
preds 非法/空→reject；`constraints_preserved` 保证用户禁项丢失即拒
（丢约束检测通过）；路由前缀未知→None 走原路径。

**3. TaskLoop 是否由真实宿主入口调用？**
调用点在 process_nlp 内（2a-pre.4c，门控），集成经 handle 直测
（p09-p13：默认关=None、白名单空=如实拒绝、files 路由真实落盘、进度
零 LLM 读台账、歧义 ask）。**未做完整 FastAPI 起服验证**（需服务环境）。

**4. 行动结果核验？**
每拍执行后重观测快照比对 add/del；"工具 ok 但状态不变"计 verify_miss
并拉黑（p04：连续 2 次后该"模板+参数"组合被排除，move 不受株连）；
MC 适配器以 SimEnv 物理为 ground truth（p14 库存实测≥8 才 COMPLETED）。

**5. verify-miss 排除机制？**
有效且边界正确：阈值=连续 2 次、精确到参数组合、核验成功即解除、
环境突变后整体重评估一次（≤2 次防抖）、**跨重启持久**（p06 恢复后
首拍不重跑已知失败）、单次偶发失败不拉黑。
