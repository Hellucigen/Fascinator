## 2. C 指标核验（定义与手工示例）

v3 §3.2 定义与审核规则逐条一致：
1. C 分母固定为全部 6 题 ✓（v3："倾向新侧的题数 / 6（全六题作分母）"）。
2. 两臂结果相同的题不计分子、保留在分母 ✓（"两臂结果一致的题计入分母、
   不计入分子"）。
3. C 衡量"六题中明确支持新侧的比例"，非"非平局题中支持比例" ✓
   （后者是 Clopper–Pearson 区间的口径，v3 已分开标注）。
4. Δ 与 C 衡量不同方面 ✓（Δ=整体准确率差；C=新侧获胜题占比）。
5. C≥5/6 是预先定义的探索性门槛，非显著性阈值 ✓（v3 明示"不是显著性
   阈值"）。
6. 不得描述为机制已证实 ✓（v3 §7：只称"达到预先定义的探索性信号"）。

**手工示例（仅定义核验，非实验数据）**：
- 示例 A：新侧胜 3 题，其余 3 题两臂相同（设 2 题两对、1 题两错）。
  新侧正确题数=3+2=5，旧侧=2+1=3 → Δ=(5−3)/6≈**33.3pp**（≥20 ✓）；
  C=3/6=**50%**（<5/6 ✗）→ **未达到**联合探索性信号。
  说明：C 在存在一致题时是更严格的约束。
- 示例 B：新侧胜 5 题、旧侧胜 1 题（无一致题）。
  Δ=(5−1)/6≈**66.7pp** ✓；C=5/6 ✓ → **达到**联合探索性信号
  （措辞限于"探索性信号"，见 v3 §7）。

## 3. 评分与失败处理核验（代码证据）

- `exact_success` 确为二元：run_llm.py:96 `"exact_success": int(exact)`，
  exact 为布尔表达式（:89-90）。✓ 与 v3 多数票前提一致。
- 错误记录路径（原实现，将被逐字移植）：调用异常 → `ans=""` + `error`
  字段（run_llm.py:126-131）；空回答 → 全零分 + 保留 error。
  评分器本身为纯字符串运算，无异常路径 ✓。
- 逐项核对任务 §三：
  1. 二元评分 ✓。2. 超时/网络/重试耗尽 → error 字段区分 ✓（原实现）；
     "无效回答"（有文本但不含 gold）按评分器正常打分——那是模型行为
     而非基础设施失败，error 字段为空，二者可区分 ✓。
  3. **缺口 G2**：v3 将无效调用计 0 票，但未明示该指标是"端到端运行
     成功率与正确性结合"的度量，也未要求**按臂单独报告基础设施失败率**
     ——若无此句，机制失败与基础设施失败在多数票层面不可区分。
  4. **缺口 G1**：有效票数为偶（基础设施失败导致，如 4 有效 2:2）时
     v3 已定义该题该臂"不可判定"、配对 d=0；但 **Δ 的分子/分母**与
     **C 的分母**在"一侧不可判定、另一侧可判定"时如何处理**未定义**
     （Δ 的"多数票正确题数"对不可判定臂无值；C 分母是否仍计 6 不明）。
  5. 见 G1 的建议规则。6. 全部规则运行前固定 ✓（v3 明示不得看结果调整）。
