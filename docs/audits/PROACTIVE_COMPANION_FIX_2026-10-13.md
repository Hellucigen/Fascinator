# Haru 主动陪伴链路修复 · 实施报告（2026-10-13 深夜）

## 1. 真实根因（不是阈值太严，是产物根本没被递到闸口）

追踪 `自主活动 → 产物 → 表达候选 → 社交决策 → 发送` 全链后，确认断点两处，都有代码证据：

**断点 A（主犯）**：CI 的社交显著性算式读 `用户-[任意]->basis` 出边（continuous_cognition.py:540-551，`user_relevance = 用户出边命中的 basis 数/3`）。Charon 工作区感知会说"我注意到…"，正是因为它建了这条边（app.py:295，注释记录着 2026-10-10 的同款根因）——**而所有生活活动产物（Activity_* 体验、调研账本、Steam 情境）都没建这条边** → `user_relevance` 恒 0 → social_relevance 垫底 → 念头永远被判成 `action` 而不是 `communication` → 根本走不到表达闸口。**不是被 SocialDecider 拒绝的，是连候选资格都没生成过。**

**断点 B**：调研的产物（找到什么/为什么卡住）只写 `living_ledger.json`（生活循环私账），图谱世界不可见——`found` 只走 P5 显式 share 通道（要求 `done` 状态），而昨晚至今她的调研全部在 `active/paused`，没有一次 done → **P5 通道零触发也是事实**（不是它坏了，是没有原料）。"卡住"更是从来没有任何形态的存在——她只会沉默地暂停。

## 2. 修了什么（3 文件，全部复用既有机制，无新候选系统）

| 文件 | 改动 |
|---|---|
| `activities.py` | **体验入图按价值三档**（走 Charon 感知同构路径，关系词用白名单内"相关"）：`high`=真发现有来源（强显著+用户边+用户关系边）；`medium`=卡住/听完歌（中档点亮，偶发一提）；`low`=随手过手（只进联想场，**无用户边=天然静默**）。`_harvest_research`：每拍对比账本，`done+findings`→high 进图、`paused`→medium"我换了几种查法没弄明白"进图（真实内容，非模板——文案由台账事实拼装，语言生成仍由既有 `_express` 完成） |
| `app.py` | Steam 事件同分档：开局/上线/退出=medium 有用户边；例行时长波动=low 静默（**不会因 Steam 变化问"还在玩吗"**） |
| 存在性 | 上一轮已修的徽标 presence 保留（那是可观测性，本报告不把它算作主动陪伴） |

**没有改的（刻意）**：SocialDecider 阈值、表达闸、去重、6/小时限速、NO_SPEAK、昼夜/心情/驱力调制——全部原样。**"何时说、说不说"完全交给既有调制系统**，产物侧只负责"把值得说的东西以正确的显著性档位放到闸口前"。

## 3. 现在能/不能的工作场景

**能**：真发现会进表达候选（high，后续受调制裁决）；研究卡住会成为 medium 候选（她可能偶尔自然说一句"拓扑那个我还没查明白"）；游戏开局/下线是 medium（偶发一提额度）；随手逛、失败查询、重复状态=不会开口。
**仍不支持**：离线推送（Charon 窗口关了消息就进不了气泡，会如实记投递失败——窗口没开时投递失败不重试，网页队列 `cc._queue` 里仍可在开发者页取走）；跨天"记得跟你说过这个"的显式对话线程延续（图谱联想是隐式的）。

## 4. 诊断方式（她为什么没说 X）

日志链已完整：`[Act] 体验入图(值档)`（产生）→ `[CC] 意图形成 kind=communication/action`（进闸资格）→ `[CC] 表达评估`（`expression_eval` 字段：v2 四轴原因 express/defer/suppress/discard 逐条可查）→ `[Charon] 投递` 成败。三问排查法：**没有体验行**=产物没到闸口（查活动本身）；**kind=action**=社交显著性不足（查用户边/档位）；**suppress/discard+理由**=调制器判定现在不该说（心情/昼夜/去重/限速），属正常。
