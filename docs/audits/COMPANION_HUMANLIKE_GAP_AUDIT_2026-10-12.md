## 1. 一页式结论

**Haru 现在能做到**：真实理解并接住用户的话（解析→图谱→沉默决策→接地回答）；对陌生概念主动查（需挂账）；注意到用户工作区的新东西（防重放已修）；在证据充分且时机合适时主动开口（今晚刚接通生活循环，尚未积累行为证据）；跨进程恢复活动账本。

**最关键的缺口（按对“像活人”的贡献排序）**：
1. **没有“生活状态”被消费**——她有什么活动/待续话题/承诺，没有任何机制在对话时读出来（living_ledger 只有生活循环自己用）；用户感受为“每次聊天从零开始”。
2. **人格不进行为**——FAS_IDENTITY 是“认知图谱系统”的自我描述而非人格；性格 traits 全仓零消费（`.trait()` 无调用点，实锤）；风格全靠 LLM 每次即兴。
3. **记忆没有时间性**——矛盾/过期/确认无处理（B10 实验实锤 episodic 无失效语义）；无摘要链，跨会话话题接续不存在。
4. **承诺不落地**——“你去读神曲”类祈使意图无识别路径（实测断链）；interaction_planner（用户 WIP）设计成熟但从未开启。
5. **可靠性硬伤**——配置热改不持久（今晚实锤：PUT 的 flag 重启即丢）、消息无幂等去重、LLM 单供应商无 failover。
6. **主动联系无用户控制**——频率/静默时段/关闭开关全部不存在（产品级缺失）。

**一句话**：Haru 的“大脑”（认知层）方向正确且与业界最先进的时序图谱方案（Graphiti）同构，但“生活”（状态层）、“性格”（人格层）、“嘴”（社交决策的产品化）三条线要么缺失要么没接线——**问题主要不是认知机制不够强，而是陪伴侧缺一层轻量的、被对话真正消费的生活-人格-社交状态系统**。

## 2. 当前架构与真实运行路径

```
用户消息 → Flask /api/nlp (app.py:3024, process_nlp ~2350 行)

  ├ 图谱感知 → 扩散激活 → topk 工作集（cognitive 仓）
  ├ dialogue_decide：行为竞争（respond/ack/ask/silence/explore，

  ├ 语言实现（ANSWER_GENERATE，prompt_templates.py:267——克制规则齐但全靠 LLM 自觉）
  └ 输出 + chat_log 落盘 + MEMORY_EXTRACT→图谱写回（app.py:2434）

后台线程（真实运行）：
  cc 认知脉冲（10-25s）→ 自由思考（15min）→ 主动表达 _express（v1 显著性门槛）
    → 队列（网页 12s 轮询）+ Charon 通道（气泡/便签）+ communicate 动作（仅 MC）
  curiosity SelfSearch（600s，需挂账问题）
  Charon inbox poller（300s，三态去重+背景降档，今晚部署）
  living_loop daemon（600s，flag 今晚接通，真实活动 life_xxx 运行中）

关键断点（图中标 ✗）：
  ✗ living_ledger（活动/发现/待续）→ 对话生成：无读取路径
  ✗ chat_log 历史 → 跨会话接续：只有 search API，无自动召回
  ✗ 祈使意图（“你去X”）→ 活动/承诺：无识别（实测）
  ✗ traits/心情 → 表达语气：认知参数层有调制，生成层无显式注入（证据有限，见 §12）

```

## 4. 实现错误 vs 机制局限（任务 §四 十类归因）

**实现错误（修代码即可）**：配置不持久化；消息无幂等；SelfSearch 相关性检查过严（v3.2 归因实验：真实相关结果被误判 irrelevant）。
**接线错误（模块在、路径断）**：SocialDecider 只被 living_loop 用，主表达路径（_express）仍走 v1；interaction_planner 三入口全默认关；traits 存储与消费断链。
**消费缺失**：living_ledger 的活动/发现/待续无人读进对话上下文；chat_log 有 search 无自动召回。
**机制缺失**：祈使意图→承诺→活动；跨会话话题接续；主动消息用户控制；摘要链/向量召回。
**机制局限（原理性）**：标量情绪对语气影响弱（调研原则 5：情绪应进状态块而非仅参数）；“显著性=价值”的单轴决策（本 session 双向实证：02:08 不该说、S5/S8 该说被漏）；episodic 无生命周期（B10）。
**架构过度复杂（陪伴侧应弱化）**：主动表达路径上“图谱 topk→信念分”链路对“该不该说”无贡献（价值判断在图谱外更简单）；回合内 2350 行单体使行为不可测。
**评测缺失**：模板话术率、不必要反问率、主动消息打扰率——全部无指标。
**模型能力边界**：ANSWER_GENERATE 规则靠自觉（“不要自动反问”实际发生率未知，需 §10 评测）。
**数据问题**：chat_log 仅 12 条（7 用户发言）——长期行为评测需真实使用积累。
**产品问题**：能力多在“后台”，用户可感知面只有聊天气泡（无状态呈现、无控制入口）。

## 5. 外部调研结论（三路，链接实测可达性已注明）

### 5.1 角色陪伴项目
- **SillyTavern**（AGPL-3.0，不可抄代码可抄机制）：字段化角色卡（description/personality/mes_example 分层进 prompt）；prompt 管理器固定装配顺序；**递归摘要链**（新摘要=旧摘要+增量，按 N 条触发，按 depth 注入）；**向量 RAG 召回旧经历**（400 字块、近 2 句做 query、relevance≥25% 取 3 条标注注入）；generate_interceptor/regex hook 做输出整形。→ 对应缺口：摘要链+向量召回+输出整形。
- **ChatHaruhi**（Apache-2.0）：风格保持靠 **few-shot 检索真实台词**而非长 prompt（embedding 选最相关样本）。→ 对 FAS 的含义：人格风格应从“她自己的历史发言”检索锚定（不违反“无台词库”原则——历史发言是她的真实行为）。
- **Open-LLM-VTuber**（MIT）：事件总线+可取消 task 实现**打断**（`[Interrupted by user]` 写入记忆）；主动开口带 `skip_memory` 元数据防自我污染；**display_text 与 tts_text 双轨**（说的≠想的）。→ 对应：打断/主动消息防污染/内心-外显分离（FAS 的 share_candidate 已是雏形）。

### 5.2 记忆与状态架构
- **Letta**（Apache-2.0）：core memory blocks（小而常驻、可被自身工具改写、字符上限强制）+ sleep-time agent（后台整理记忆，编辑工具只挂后台）。→ **FAS 最该抄的是“常驻可编辑身份块”**；不抄整套分页框架（图谱已是检索层）。
- **Mem0**（Apache-2.0）：ADD/UPDATE/DELETE 判别式管道**已被其自己弃用**（2.x 转 ADD-only+链接+hash 去重）——教训：破坏性记忆更新不可靠；检索三信号融合（semantic+BM25+entity boost）。
- **Zep/Graphiti**（Apache-2.0，与 FAS 最同构）：**双时间线边**（valid_at/invalid_at/expired_at + episodes 溯源；矛盾=旧边失效而非删除→保留“我记得你以前…”）；hybrid 检索+RRF 重排。LongMemEval +18.5%（厂商自评，注意偏差）。→ **FAS 记忆升级的蓝本**：给边加时间有效性与 episode 引用，图谱骨架不动。
- **Generative Agents**（arXiv:2304.03442）：检索三因子 recency×importance×relevance；**reflection 按 importance 阈值触发**蒸馏高层认知；消融实验证明 reflection 对可信度贡献显著（TrueSkill 29.89→26.88 去掉即掉）。→ FAS 缺 importance 因子与“反思→人格/关系认知”的陪伴化闭环。

### 5.3 主动对话与运行时
- **OpenClaw**：心跳（30m-1h 完整 agent 轮，**无事产出 NO_REPLY 显式抑制协议**）+ activeHours 静默段 + flood guard（30s 最小间隔/60s 内 5 次上限）+ 忙时推迟 + 每类触发独立开关/投递三模式（含全静默）。→ **主动联系的产品化范式**，与 FAS living_loop/SocialDecider 结构同构，四件套可直接映射。
- **主动对话研究**：CHI 2025（arXiv:2410.04596）主动发言增益取决于**与用户当前上下文关联**；Memory Reviver（2501.15408）在合适轮次交付记忆内容促进回忆；MapDia（2503.05150）主动转题须由检索到的个人记忆支撑；通知研究（1712.07120）预测“发了也没人看”则不发。
- **Replika 反面清单**（arXiv:2606.04431 inverse-RL 审计、2412.14190、2509.22505、2410.20130）：主动在场/提问策略随用户脆弱性漂移服务留存；依恋被机制改动伤害真实用户。→ **红线：FAS 主动性以“表达/分享”为限，禁止召回式话术，不以参与度为优化目标。**

```
   └──────────┘        │ (app.py │    │(策略约束+   │   │  落盘    │
        事件触发 ──────▶│  收敛为  │    │ 风格锚)    │   └──────────
   ┌──────────┐        │  装配层) │    └────────────┘
   │ 生活循环 │──候选──▶│          │◀──祈使意图→承诺→活动（G4）

   └──────────┘  协议    └────┬────┘

                    ┌────────▼─────────┐   用户控制层（新）：

                    │  双时间线边升级） │
                    └──────────────────┘
```

- **对话发生**：消息→编排层装配（persona 块+生活状态摘要+召回片段+图谱 topk）→生成→落盘（回合尾：记忆写回+状态更新+承诺识别）。
- **无用户消息**：心跳轮（预算内，产出 NO_REPLY 或候选）+ living_loop 探索 + sleep-time 整理（摘要/反思/身份块更新——**编辑工具只挂后台**，Letta 原则）。
- **主动联系**：触发源四类（事件/心跳/日程/整理产出）→统一表达裁决（SocialDecider 扩展：证据+新颖+时机+**用户响应预测**+频控/静默段）→ 发送带状态记录（pending/sent/failed 区分，OVT skip_memory 防自我污染）。
- **失败/重启**：配置持久化（写 data/config_overrides.json）；消息幂等（msg_id 去重表）；LLM 降级链（多供应商配置）；状态块与账本原子写。
- **与 Cognitive 边界**：陪伴侧只依赖 解析/检索/写回/反思 四个 API 面；主动路径的“该不该说”判断**全部留在陪伴侧**（认知侧不背社交决策）。

## 10. 评测计划（任务 §八 十项全覆盖）

**自动检查（可靠性）**：重启恢复一致性（配置/账本/去重表）；消息幂等（重放注入测试）；预算边界（耗尽→静默）；LLM 故障注入（降级链生效）；主动频控（超限必压）。
**行为评测（对话样本+盲评）**：
1. 跨会话连续性：隔天重开，引用昨日话题的正确率；
2. 共同经历引用：注入 3 周模拟历史后提问“我们聊过X吗”，正确/幻觉/“不记得”三态合理性；
3. 偏好持续影响：声明忌口后 5 轮内推荐是否遵守；
4. 人格一致性：同情境 10 次生成的风格方差（成对盲评）+ 立场坚持率（被反驳时）；
5. 闲聊自然度：幽默/接梗样本集（20 条）成对比较 vs 现版本；
6. **模板率与不必要反问率**：正则+人工双标注（“我理解你/听起来”清单、反问率），目标 <现版本基线；
7. 主动消息：回放 7 天事件流，人工盲评每条 share/silent 判定的合理率与打扰率（含 02:08 反例、S5 正例锚点）；
8. 记忆矛盾：注入“以前养猫→现在没了”，验证失效不删除的回忆表达；
9. 任务失败一致性：断网注入，验证不谎报成功（v3.2 机制回归）；
10. 长期运行：living_loop 7 天观察（重复活动率/预算/账本健康）。
成对比较用同模型同预算；主观项双人盲评；**不以 token/调用数/存储量增长冒充体验改善**。

## 11. 需要项目所有者决定的问题

1. **人格内容**：Haru 的性格/偏好/立场需要一次有意识的定义（当前只有“发育中的认知系统”自我描述）——由谁写、写多具体、允许多大漂移。
2. **风格锚的来源**：用她自己的历史发言做 few-shot（ChatHaruhi 式）与“无台词库”原则是否兼容——我的判断：兼容（历史发言是她的行为不是脚本），但需你确认。
3. **认知仓授权**：双时间线边属性需要改 FAS-Cognitive（graph_model/写回路径）——第 4 期前需明确授权。
4. **主动默认频率**：心跳间隔与每日主动消息预算的默认值（建议保守：日 ≤2、静默段 23:00-08:00）。
5. **表现层投入**：打断/在线状态/语音（P2）是否进本轮路线。
6. **Replika 红线确认**：主动性永远不以“让用户回来”为优化目标——写进设计约束。
