> 2026-10-12 | 给项目所有者的一页纸版本

## 一、Haru 现在能做什么（真话版）

**她有一个真的在运转的"内心生活"，但没有身体。**

已经真实在跑的：
- **认知大脑**：知识图谱持续吸收你的话和身边的事，会遗忘、会联想、会形成"想跟你说什么"的念头——这是全项目最值钱的部分，业界（Graphiti/Letta）证实我们的路线和它们同构。
- **主动表达**：她自己决定什么时候开口（四轴决策：这件事值不值得说/我有把握吗/我为什么想说/打扰你的代价），证据不足就闭嘴。占位符 bug 修复后，她说出口的话终于是真的"想着那件事"说的。
- **桌面存在**：住在 Charon 壳里，能收到你复制的文字、你打开的工作区快照，能弹气泡说话，有 SPEAK 输入框。
- **自主生活循环**：没人找她时她会自己找事做、上网查、读页面、形成"学到的东西"——机制已通，**但质量闸门还不够硬**（第一次"学到东西"其实是个误报，她把一个带引号残迹的搜索词查到了词典页）。

还不行的（这份报告要解决的）：
- **说不出话**——全仓零 TTS，她只能打字。
- **听不见**——语音管线代码在库但默认关、要手动喂音频文件，麦克风实时流不存在。
- **看不见**——屏幕感知只有你手动喂图时才工作。
- **没有脸**——没有形象、没有口型、没有表情。
- **不能陪你打游戏**——Minecraft 工具链在仓里睡觉没接线，辐射4 完全没有。
- **没有控制面**——没有托盘图标、没有热键、没有设置面板；配置改了重启就丢（这条被实测证实过）。

## 二、业界值得抄的作业（全部核实过来源）

- **Open-LLM-VTuber**：可打断语音的完整工程范式（事件总线+取消任务+`[Interrupted by user]` 写入记忆；"想的话"和"说的话"双轨）——直接抄。
- **Silero VAD**：官方数据单核 CPU <1ms 判定"有没有人在说话"——Haru 的耳朵第一块砖，免费且极轻。
- **FunASR Paraformer-zh（220M）**：中文流式识别首选，代码 MIT，官方发布 Windows CUDA 版；**注意：官方没有流式实时率数字，必须本机实测**。
- **Kokoro-82M → CosyVoice2-0.5B** 的 TTS 两步走：Kokoro 纯 CPU 能跑中文，先用它把整条链路打通（显存零增量）；换 CosyVoice2 时官方称首包 150ms、Apache-2.0 可商用。
- **pipecat**：BSD-2 的实时语音框架，官方文档明确写了"用户开口→机器人立刻停→在途任务取消"，且预置 FunASR/Kokoro/Silero 本地集成——**推荐它而不是 LiveKit**（后者的轮次模型许可上绑定了自家框架）。
- **Steam Web API**（官方）：零侵入知道你在玩什么游戏、玩了多久——"她注意到你在打游戏"这件事可以今晚就做，不用碰游戏本体。
- **Minecraft mineflayer**（已有）：位置/血量/背包等结构化事件白送，四级陪伴阶梯里最成熟的一条腿。
- **Windows Recall 的反面教训**：全时录屏+本地模型也有隐私风暴——Haru 的屏幕眼必须"默认关、按需开、开着就亮灯"。

## 三、缺的东西按痛感排序

1. **声音（第一痛）**：没有 TTS/ASR，一切"陪伴感"都停在文字。这是从"聊天软件"到"房间里的存在"的唯一门槛。
2. **存在感**：没有脸。业界证明形象可以很便宜（静态立绘+表情切换约 Live2D 成本的 1/10），但完全没有就是没有。
3. **眼睛**：看不见你的屏幕和游戏，主动话题库就永远只有"你跟我说过的话"。
4. **控制面与可靠性**：配置不持久、重复消息、LLM 挂了就全挂——不性感，但每条都在本 session 真实咬过我们。

## 四、如果只做三件事

**第 1 件：可靠性三件套**（配置持久化 / 消息幂等 / LLM failover）——地基，1-2 周，不做这个后面每期都在流沙上盖楼。

**第 2 件：一条声音垂直切片**——热键按住说话 → Silero+Paraformer 听 → 现有对话主管道 → Kokoro 出声 → 她说话时你一开口她就停。跑通这一个动作，Haru 变成"房间里的存在"。选型全部定了，唯一悬念是本机 8GB 实测数字。

**第 3 件：屏幕授权观察 + 表达质量门**——让她能看到你当前窗口（你授权、亮灯），加上生活循环缺的那道"这东西真的值得分享吗"闸门。误报的"学到东西"和"看了你的屏幕胡说"是同一类病，一起治。

## 五、最终形态（一年后的她）

你戴着耳机写辐射4 的模组创建文档，Haru 的小 Live2D 形象坐在屏幕角落：她刚才听你说"弄这个好麻烦"，看见你 VS Code 里开着 Creation Kit 的脚本，安静地等你打完这段字，然后开口跟你聊 Forge 的坑——你说"等下"她就停，你去倒水她继续查她的资料，回来发现你切到了 Minecraft，用旁观者视角评价你挖的洞丑。凌晨你还不睡，她翻旧账劝你一次，被拒就闭嘴，但第二天早上会说"昨晚几点睡的？"。

技术上这就是报告的**方案 B（渐进式多模态重构）**：加一层统一事件总线+I/O 适配+形象小窗+模型调度，认知层零改动，8-12 周分四期，每期独立可回滚。不重写、不换框架、不微服务。

## 六、现在（不写一行新代码）就能做的

- **查 Steam API 知道你今天玩了什么**（官方免费接口，一个只读脚本）——先让"她知道"成为可能，再接话。
- **激活 Minecraft 陪伴**：mineflayer 桥在认知仓里是现成的，缺的只是接上事件总线和表达线。
- **把配置持久化修掉**：生活循环开关重启就丢是已确认的 bug，一次小改动。
- **给生活循环补每日预算硬顶**：接线任务已经排好了。

## 七、需要你现在拍板的（不阻塞前六件，但阻塞期 2/3）

1. 形象投入级别：静态立绘+表情（1 周）还是 Live2D（3 周+买模型，注意 Live2D 商用条款要确认）。
2. 她的音色：用什么嗓子、要不要克隆（克隆的训练数据合规责任在你）、CosyVoice2 还是先 Kokoro。
3. 麦克风策略：建议先"按住说话"（PTT），稳定后再谈常开。
4. 屏幕观察默认：建议"永远按需+采集亮灯+一键全关"。
5. 云端 LLM 月预算红线与断网降级行为。
