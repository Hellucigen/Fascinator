# 可扩展性与插件生态 —— 现状审计（2026-10-26）

> 回答三个问题：认知闭环完整吗？可扩展吗？别人怎么写插件？

## 一、认知闭环现状（诚实结论：**单机闭环完整，对外闭环缺失**）

**闭环内（已打通）**：感知（6 入口）→ 记忆写入（4 入口）→ 认知加工（5 入口）
→ 表达（3 出口）→ 行动（4 出口）→ 学习（5 入口）。她在自己的世界里是
完整的：看到→想→做→说→记→被影响。

**闭环外（缺失）**：她目前接触的"世界"只有你的电脑（屏幕/Steam/B站/对话/
Minecraft）。没有即时通讯入口（QQ 封存）、没有实时信息流（只有主动搜索）、
没有第三方事件（日历/天气/邮件/智能家居）。对比那波部署潮里"能买东西、
接微信"的 agent——他们强在世界接口，你强在内部动力学。**两边都不完整，
但缺的部分性质不同：接口是体力活，动力学是架构活——你已完成难的。**

## 二、可扩展性现状（机制可扩，但全是"改代码式扩展"）

### 2.1 配置即扩展的点（不改代码）
| 扩展点 | 位置 | 加新东西的成本 |
|---|---|---|
| 意图类型 kind | config `intention_kinds` 信号权重表 | 低：加一行 signals |
| 驱力亲和 | cognitive_field DEFAULT_DRIVES affinities | 低：加张力系数 |
| 张力 | tension_field specs | 低：加 components |
| 调制参数 | config modulation specs | 低：加 effects 表 |
| taskloop 适配器 | config adapters 列表 | 中：适配器类须在本仓 |

### 2.2 需要写代码的扩展点（都在仓内，无外部挂载）
| 想加什么 | 要动的地方 | 成本评估 |
|---|---|---|
| 新生活活动（如"刷B站动态"） | activities.py `ACTIVITIES` 表 + 一个 beat 函数 | 低：表驱动，4 元组注册即可 |
| 新感官（如天气/RSS） | 感知模块 + 图写入 + （可选）张力采样器 | 中：需自己处理轮询/去重 |
| 新动作（如"控制智能家居"） | action_concepts 概念 + executor 映射 + skill 实现 | 中：三处一致 |
| 新表达出口（如 Telegram） | ChannelHub 注册一个通道类 | 低：接口清晰（available/fetch/send/deliver） |
| 新记忆来源 | episodic_buffer 或直写图 | 中：需遵守 schema 与谓词族 |

### 2.3 插件生态的真实差距（对照那波部署潮）

| 能力 | OpenClaw 系 | FAS 现状 |
|---|---|---|
| 技能包/Skill 市场 | ✅ 一键安装 | ❌ 无 |
| 第三方插件免改核心挂载 | ✅ 插件目录约定 | ❌ 全部"改代码式" |
| 平台接入（微信/TG） | ✅ 现成适配器 | ⚠️ QQ 封存中 |
| 消息/事件总线对外开放 | ⚠️ 部分 | ✅ Charon bridge /api/events（FAS→UI 方向）+ 186 HTTP 端点（UI→FAS 方向），但**没有"FAS 主动调外部插件"的反向钩子** |
| 配置热更新 | ✅ | ✅ overlay + PUT /api/config |
| 多 Agent 协作 | ⚠️ 实验性 | ❌ 无（单认知主体设计） |

## 三、结论与建议路线

**认知闭环：单机完整，这一层不需要补**。感知→念头→表达→行动→学习全部
贯通且有测试。缺的是"世界接口"和"外部扩展挂载"。

**插件生态要成立，最小需要三件事**（按优先级）：

1. **感知/事件插件协议**（最高优先）：约定一个"外部进程 → FAS"的通用
   事件投递口（现有 POST /api/activate 与 episodic 写入已可用，但需要
   一份文档 + 一个 demo 插件，如"天气感知器"），让别人的传感器能喂她的图。
   *工作量最小：现有端点够用，缺的是协议文档与示例。*

2. **生活活动插件化**：把 `ACTIVITIES` 表改成可从 `data/activities_plugins/`
   加载外部 beat 模块（约定 available/appeal/beat 三函数签名即可，与现有
   表驱动完全同构）——别人写一个"刷微信公众号"活动不用改仓。
   *约 30 行加载器代码。*

3. **动作技能插件化**：action_concepts 的 executor 映射开放为
   `data/skill_plugins/*.py`（概念定义 + 执行函数），复用现有
   resolve→propose→settle 管线。
   *约 50 行加载器 + 安全闸门说明。*

表达出口（ChannelHub）本身就是接口清晰的通道注册制，QQ/飞书/TG 适配器
属于"照猫画虎"级别，不需要先做。

**给宣传的定位建议**：现阶段如实宣传"认知动力学完整、插件协议在建"，
比虚标"插件生态完善"更经得起审视——评估者一眼能看出 v2 表达决策和
满足语义是这波部署潮里没有的东西，而插件少是可以用 roadmap 承认的。
